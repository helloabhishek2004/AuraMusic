# Security Policy

The AuraMusic team takes the security and privacy of our users seriously. We appreciate responsible disclosure of security vulnerabilities.

---

## Supported Versions

Only the latest release/beta version is actively maintained with security updates.

| Version | Supported          |
| ------- | ------------------ |
| 3.0.0   | :white_check_mark: |
| < 3.0.0 | :x:                |

---

## Reporting a Vulnerability

**Please do NOT disclose security vulnerabilities publicly through open GitHub Issues.**

If you believe you have discovered a security vulnerability in AuraMusic:

1. **GitHub Private Vulnerability Reporting**:
   Use GitHub's built-in [Security Advisories](https://github.com/helloabhishek2004/AuraMusic/security/advisories/new) feature to submit an advisory draft privately.
2. If GitHub Advisory reporting is unavailable, reach out to the project maintainers through private GitHub messaging or repository contacts before public disclosure.

### What to Include in Your Report
To help us triage and resolve the issue quickly, please include:
* Description of the vulnerability and its potential impact.
* Affected components (e.g., native stream resolver, Room database persistence, bridge serialization).
* Step-by-step instructions or proof-of-concept (PoC) demonstrating how to reproduce the issue.
* Any suggested mitigations or patches if you have identified them.

### Our Commitment
* We will acknowledge receipt of your vulnerability report within 72 hours.
* We will provide an estimated timeline for investigation and resolution.
* Once patched, an update will be published and credit will be given in the release notes (unless anonymity is requested).
